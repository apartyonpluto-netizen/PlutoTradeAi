Ambiguous Order Submissions

{{ pending_ambiguous_submissions|length }} frozen

An entry lands here when the broker's response to an order submission could not be conclusively determined (a timeout, dropped connection, or similar) - the affected account's autonomous entries are frozen until this is resolved. Resolving ALWAYS re-checks order detail, open orders, positions, and order history fresh, right now, regardless of what's shown below - never trust a stale view. "Release" only succeeds if all four checks come back completely clean (a check that fails, times out, or returns an incomplete/truncated result blocks release just like finding a match would); "Link" only succeeds if a match was found that's strongly correlated to this specific order (client order ID, or quantity/price/time-plausible), not merely a same-ticker position that could belong to unrelated activity - and a linked filled or partially filled order immediately enters normal fill-protection handling, it does not just clear the freeze. Every resolution requires typed confirmation of the ticker and is written to a tamper-evident, hash-chained audit record before the freeze is released - not a claim of immutability; anyone with direct disk access could still alter the underlying file, but doing so is then detectable.
